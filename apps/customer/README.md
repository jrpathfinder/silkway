# Мобильное приложение «Шелковый путь»

Flutter-приложение сети чайхан. Из одной кодовой базы собираются **два**
приложения (флейворы) — они отличаются только точкой входа и набором экранов:

| Флейвор | Точка входа | Для кого |
|---|---|---|
| `customer` | `lib/main_customer.dart` | покупатель: меню, корзина, заказы |
| `courier`  | `lib/main_courier.dart`  | курьер: приём и отказ от заказов |

## Запуск

```bash
flutter run -t lib/main_customer.dart          # на моках, бэкенд не нужен
flutter run -t lib/main_customer.dart --dart-define=USE_MOCKS=false
flutter test
```

По умолчанию `USE_MOCKS=true` — приложение работает целиком на моках, без
запущенного API. Это же значение используют тесты.

## Как устроен код

```
lib/
  app/          сборка приложения и флейворы
  core/
    ports/      контракты доступа к данным (абстрактные классы)
    models/     модели, общие для всех фич
    network/    HTTP-клиент
    storage/    защищённое хранилище (токены) и обычное (флаги, ключи)
    design_system/  общие виджеты и тема
  features/<фича>/
    data/           реализации контрактов: *_mock и *_http
    application/    состояние, не привязанное к экрану
    presentation/   экраны, и providers/ — переключатель мок/HTTP
  routing/      таблица маршрутов и гейты доступа
```

**Ключевой приём — контракты вместо конкретных реализаций.** Экраны зависят
от интерфейса из `core/ports`, а какая реализация подставится (мок или HTTP),
решает провайдер в `features/<фича>/presentation/providers/` по значению
`Env.useMocks`. Благодаря этому приложение целиком работает без бэкенда, а
тесты не нуждаются в сети.

## Покупательский поток

```
заставка -> меню (выбор ресторана) -> карточка блюда -> корзина
         -> оформление [нужен вход] -> оплата -> статус заказа
```

Вход по SMS-коду требуется **только на оформлении** — каталог и корзина
открыты всем. За это отвечает `checkoutRedirectGuard` в `routing/`.

Две вещи, которые легко сломать при доработке:

- **Цены считает сервер.** Суммы в корзине — клиентская оценка для показа.
  При создании заказа бэкенд заново берёт каталог и пересчитывает стоимость.
- **Идемпотентность заказа.** Ключ хранится по «отпечатку» корзины и
  переживает перезапуск приложения, поэтому повторная отправка не создаёт
  второй заказ (`core/utils/idempotency_key_store.dart`).

## Заставка

Заставок две. Первую показывает ОС, пока грузится движок Flutter, — она может
быть только картинкой (настройки в `pubspec.yaml`, секция
`flutter_native_splash`). Вторая — `features/splash/`: та же картинка плавно
переходит в интерьер чайханы.

Видео отсюда убрано намеренно: раскрутка декодера занимала ~2 секунды до
первого кадра. Обе сцены — статичные картинки, кодеков в старте нет.

`SplashGate` показывает заставку не чаще раза в 6 часов: первый запуск за день
с заставкой, остальные открывают меню сразу.

## Что уже реально, а что заглушка

| Область | Состояние |
|---|---|
| Каталог, рестораны | работают с бэкендом |
| Заказы | создание и статус — да; история — только моки, роута нет |
| Оплата | создание платёжной сессии есть |
| Вход по SMS | на бэкенде dev-заглушка: код `0000`, статические токены |
| Лояльность, курьер | только моки, модулей на бэкенде нет |
| Карты | заглушка, без ключей MapKit |

## Тесты

```bash
flutter test
```

Виджет-тесты поднимают приложение на моках и проходят потоки целиком
(каталог, корзина, оформление с входом). Хелперы — в `test/helpers/`;
`pumpAppPastSplash` поднимает приложение и пропускает заставку.
