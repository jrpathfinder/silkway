# ADR-001: Модульный монолит для MVP

## Решение

Использовать NestJS-модульный монолит с явными доменными границами, портами и событиями.

## Почему

- Одна ресторанная точка и одна команда не требуют распределенной эксплуатации.
- Транзакции заказа, оплаты и наличия проще сохранять в одной БД.
- Провайдеры изолированы портами и могут быть заменены.
- Позже модули можно вынести в отдельные сервисы по нагрузке и ownership.

## Ограничения

Модули не должны импортировать внутренние классы друг друга; обмен выполняется через публичные сервисы, контракты и события.
