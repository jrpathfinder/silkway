## Что это за проект

Платформа доставки еды для ресторана среднеазиатской кухни, MVP-объём: одна точка в Москве, реальное меню (импортировано из настоящего листинга ресторана в Яндекс.Еде). Три приложения в одном npm-workspace:

| Приложение | Стек | Состояние |
|---|---|---|
| `apps/api` | NestJS, модульный монолит, Postgres (опционален в рантайме) | Основной поток заказ/каталог/авторизация реален и протестирован; часть интеграций всё ещё мок |
| `apps/admin` | Vite + React | Реален — вход по паролю, заказы, CRUD каталога, акции, импорт/экспорт |
| `apps/customer` | Flutter, два флейвора (`customer` + `courier`) | Реален — полный поток заказа, настоящая оплата, передача заказа курьеру |

## Архитектура в общих чертах

**Модульный монолит** (см. [ADR-001](../../adr/001-modular-monolith.md)): один процесс NestJS, одна база Postgres, модули в `apps/api/src/modules/*` (`health`, `locations`, `catalog`, `auth`, `admin`, `orders`, `integrations`), которые обращаются друг к другу только через экспортированные сервисы/контроллеры — никогда не лезут во внутренности другого модуля.

**Порты и адаптеры** (см. [ADR-002](../../adr/002-provider-adapters.md)): каждый внешний провайдер (оплата, SMS, доставка, маркетплейс) стоит за абстрактным портом в `apps/api/src/modules/integrations/ports/`. Конкретные провайдеры привязываются через переменные окружения в `integrations.module.ts`, по умолчанию всегда мок — так приложение запускается вообще без внешних аккаунтов. Точный текущий статус — в [Статусе интеграций](./integrations.md).

**Доменный поток**: покупатель выбирает точку → серверная цена корзины → заказ создаётся в статусе `PENDING_PAYMENT` → платёжный адаптер создаёт хостинг-чекаут → подтверждённый вебхук (или, для мока, ручной dev-эндпоинт) переводит заказ в `PAID` → персонал принимает/готовит/переводит в готовность в админ-панели → курьер принимает и доставляет. Каждый переход статуса проверяется сервером относительно текущего состояния заказа — нет лазейки «поставить любой статус».

**Что всё ещё полностью в памяти**: `OrdersService` — это `Map`, а не таблицы Postgres, которые для него уже описаны в `schema.sql`. Перезапуск бэкенда теряет все заказы. Это осознанный, а не случайный пробел MVP — не удивляйтесь, если тестовые заказы исчезают после перезапуска.
