# Локальная разработка и тестирование

EN: [`../en/local-dev.md`](../en/local-dev.md). Обновляйте обе версии вместе.

## Запуск стека

```bash
npm install
cp apps/api/.env.example apps/api/.env
docker compose -f infra/docker-compose.yml up -d      # Postgres + Redis
npm --workspace apps/api run start:dev                 # API, порт 3000
cd apps/admin && npm run dev                            # админ-панель, порт 5173
```

**Сон macOS убивает и Docker, и любые фоновые dev-серверы.** Если Мак засыпал, скорее всего понадобится: `open -a Docker` (дождаться демона), снова `docker compose ... up -d`, и заново `start:dev`/`npm run dev` для всего, что было запущено в фоне. Проверяйте это первым делом, когда то, что только что работало, вдруг не может подключиться.

## Тестирование Flutter-приложений

Два флейвора, одна кодовая база: `lib/main_customer.dart` / `lib/main_courier.dart`. Собирается с `--dart-define=USE_MOCKS=false` для работы с настоящим бэкендом, `API_BASE_URL` указывает туда, откуда бэкенд реально доступен (см. ниже).

### iOS Simulator

Симулятор напрямую достаёт до `localhost` самого Мака — самый простой путь, настройка сети не нужна. Два одновременно запущенных симулятора получают отдельные окна и могут гонять customer + courier бок о бок вообще без трюка с bundle ID, так как это разные устройства.

**Координаты тапа — в поинтах устройства, не в пикселях скриншота.** Для iPhone 16 Pro это 402×874 — рассуждайте сразу в этом пространстве координат (например, «эта кнопка примерно на 90% высоты экрана» → y≈786), а не оценивайте по пиксельным размерам самого изображения скриншота и передавайте эти числа как есть. Координата вне диапазона 0–402 / 0–874 молча попадает в никуда.

### Физическое устройство

Устройство не достаёт до `localhost` Мака — `API_BASE_URL` должен указывать на реальный LAN-адрес Мака, и оба должны быть доступны друг другу. Три реальных грабли, каждая стоила реального времени на отладку:

1. **Публичный/гостевой Wi-Fi часто блокирует трафик между устройствами** (client isolation) — телефон и Мак могут быть на «одной и той же» Wi-Fi отеля/кафе и при этом вообще не доставать друг до друга, запросы висят до таймаута, а не быстро падают с ошибкой. Если сборка на физическом устройстве, которая раньше работала, вдруг не достаёт до бэкенда — прежде чем отлаживать код, проверьте, в какой сети сейчас реально Мак. Надёжное решение: включить личную точку доступа (Personal Hotspot) на телефоне и подключить к ней Мак — у хотспота нет изоляции между двумя его же устройствами.
2. **iOS по умолчанию блокирует обычный HTTP (App Transport Security)** — Simulator тихо исключает `localhost` из этого правила, именно поэтому сборка на физическом устройстве может не работать там, где идентичная сборка в симуляторе работает. Нужен `NSAppTransportSecurity` / `NSAllowsArbitraryLoads` в `ios/Runner/Info.plist` для dev-бэкенда на обычном HTTP. (Не понадобится после появления настоящего деплоя с HTTPS.)
3. **Local Network Privacy в iOS 14+** блокирует соединения с любым приватным IP (192.168.x, 172.16–31.x — включая диапазон Personal Hotspot 172.20.10.x), пока в `Info.plist` не объявлен `NSLocalNetworkUsageDescription`. И снова Simulator это ограничение вообще не применяет, поэтому там оно никогда не проявляется.

Оба приложения делят один `ios/Runner/Info.plist` и один Xcode-проект — фикс `NSAppTransportSecurity` должен быть **постоянным** изменением (он в репозитории). Сборке courier-флейвора со своим bundle ID (чтобы установить его рядом с customer-флейвором на одном физическом устройстве) сейчас делается через **временный** `sed`-оверрайд `PRODUCT_BUNDLE_IDENTIFIER` в `project.pbxproj` именно для этой сборки, откатывается сразу после — не коммитится. Если courier должен регулярно сосуществовать с customer на устройстве, это стоит превратить в настоящую настройку флейвора/схемы в Xcode, а не повторять этот танец каждый раз.

## Состояние бэкенда сбрасывается при перезапуске

`OrdersService` — в памяти, каждый перезапуск (включая те, что нужны после того, как Мак проснулся и сервисы пришлось поднимать заново) стирает все заказы. Не удивляйтесь, если заказ, который пять минут назад был `DELIVERED`, просто исчез.
